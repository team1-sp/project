# Requirement changes: #160

Decided by: DEC-065 (srs.fr.14.15); DEC-160.1 (normal mode becomes windowed mode)

## Reword srs.fr.14.15
- **srs.fr.14.15** When the user drags a panel tab out of its dock and drops it where no dock accepts it, the Editor shall show the panel as a floating panel inside the main window.

## Reword srs.fr.1.1
- **srs.fr.1.1** In windowed mode, the Engine shall execute each render frame in this order: (1) collect keyboard input from the operating system, (2) run the number of simulation ticks given by srs.fr.1.3, each as defined in srs.fr.1.12, (3) render the state left by the last completed tick, (4) present the image.

## Reword srs.fr.1.3
- **srs.fr.1.3** In windowed mode, while the game loop is not paused, the Engine shall in each render frame run one simulation tick for each whole 1/60 s of real time that has elapsed and not yet been simulated, up to a maximum of 5 ticks per render frame, and carry any part of a tick that remains over to the next render frame.

## Reword srs.fr.1.7
- **srs.fr.1.7** The Engine shall provide two run modes: windowed mode, which opens a window and runs render frames, and headless mode, which runs simulation ticks without a window and without render frames.

## Reword srs.fr.1.9
- **srs.fr.1.9** When the Engine runs as a standalone game in windowed mode (a built game started without `--headless`, Build and Run, or a game started outside the Editor), it shall open an application window whose size and fullscreen state are taken from the project's Rendering settings (srs.fr.27.23); a built game started with `--headless` shall open no window and run as stated in srs.fr.7.1 and srs.fr.7.2; in Play mode inside the Editor, the game shall render in the Game view at its Resolution ▾ size (srs.fr.20.2, srs.fr.20.3).

## Reword srs.fr.1.10
- **srs.fr.1.10** When the user closes the game window in windowed mode, the Engine shall finish the current render frame, release every physics, rendering and file resource it holds, and exit with exit code 0.

## Reword srs.fr.1.14
- **srs.fr.1.14** In the input application phase, the Engine shall give the tick the input action state of its input source (srs.fr.5.11), built from action transitions by the rules of srs.fr.5.6; in windowed mode the transitions come from the keyboard queue of srs.fr.5.5.

## Reword srs.fr.4.1
- **srs.fr.4.1** In windowed mode, the Engine shall draw every enabled entity that has a Position component and an enabled Sprite component at its world position, rotation and scale, composed through its parents as stated in srs.fr.3.37.

## Reword srs.fr.4.10
- **srs.fr.4.10** In windowed mode, the Engine shall limit only the render frame rate, never the length of a simulation tick: when VSync is on, it shall request presentation synchronized with the monitor refresh rate and ignore Target FPS; when VSync is off, it shall limit render frames to the Target FPS value, where 0 means no limit.

## Reword srs.fr.4.20
- **srs.fr.4.20** In windowed mode, when a run starts, the Engine shall play the clip of every enabled Audio Source whose play on start is on, and shall repeat it when loop is on.

## Reword srs.fr.5.5
- **srs.fr.5.5** In windowed mode, the Engine shall queue the keyboard transitions collected in each render frame as an ordered list of (action, down or up) in the order they occurred, and the first simulation tick that runs afterwards shall consume the whole list; when a render frame runs no tick, the list shall stay queued for the next tick.

## Reword srs.fr.5.7
- **srs.fr.5.7** Pressed and released states shall last only for the tick that consumed them, and held states shall last until a tick consumes an up transition or a focus-lost marker (srs.fr.5.8), in windowed mode, in recording playback and for the Playtest Agent alike.

## Reword srs.fr.5.11
- **srs.fr.5.11** Each simulation tick shall take its input action state from exactly one input source: None (no actions in any tick), the keyboard (windowed mode only), an input recording, or the Playtest Agent; the Engine shall ignore the keyboard while another source is active.

## Reword srs.fr.5.13
- **srs.fr.5.13** When an input recording is played back, the Engine shall start with no action held, apply at each tick the ordered list of that tick's entry by the rules of srs.fr.5.6 and srs.fr.5.10, keep held actions held between entries, and give no pressed or released actions in ticks without an entry, so that windowed-mode and headless runs read the same recording identically.

## Reword srs.fr.7.6
- **srs.fr.7.6** On the same computer, two runs shall produce the same entity positions, velocities and events at every tick number, whether each run is headless or in windowed mode, when they have all the prerequisites of srs.fr.7.28; determinism across computers, operating systems or builds is not required.

## Reword srs.fr.17.9
- **srs.fr.17.9** When the user clicks Play or presses Ctrl+P with a project open, no compile errors, the mode switch on Windowed and no simulation operation going (srs.fr.17.28), the Editor shall save a Play mode snapshot (srs.fr.17.24), start the game loop in windowed mode with every loaded scene, turn the Play button blue, tint the window as stated in srs.fr.17.17 and focus the Game tab.

## Reword srs.fr.17.19
- **srs.fr.17.19** The mode switch shall offer Windowed and Headless and shall be enabled only while the game is not playing.
